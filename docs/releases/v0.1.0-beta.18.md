# `v0.1.0-beta.18`

Beta.18 publica el perfil sellado `sealed-export/v1` completo (ADR-0042,
issue #46): cifrado del respaldo en reposo como extra opcional `[sealed]`,
sin romper el camino `export/v1` en claro.

El contexto gestionado y la plantilla administrada permanecen en
`0.1.0-beta.11`. Esta release no cambia almacenamiento físico, política
de autoridad ni el contrato `plan-write → commit-write-plan`.

## Cambios principales

- **`export create --seal sealed-export/v1`**: cifrado AES-256-GCM por
  entrada con nonce contador inyectivo y AAD por entrada; subclaves
  HKDF-SHA256 separadas por propósito (la CEK raíz jamás es clave AES
  directa); CEK efímera por bundle custodiada por un **adaptador externo
  de claves** (`--key-adapter`/`--key-adapter-arg`/`--key-adapter-env`,
  argv estructurado sin shell, contrato JSON por stdio, runner acotado:
  límites I/O, timeout de 30 s, terminación del árbol de procesos).
  Manifiesto `export-manifest-v2` con `manifest_mac` HMAC-SHA256 sobre
  el transcript completo; publicación con staging + renombrado atómico.
- **`export verify` dual**: sin clave es estructural — jamás
  `verified: true`, enum cerrado de `diagnostics`; con adaptador,
  autenticado completo (AEAD + MAC + `content_sha256` del plano).
- **`export restore` sellado**: desencripta TODO antes de tocar el
  destino; semántica v1 intacta (no-overwrite, no-merge). Sin
  degradación a claro en ningún borde: sin adaptador →
  `sealing_adapter_required`; sin extra → `sealing_extra_not_installed`;
  downgrade o perfil desconocido → `unsupported_export_profile`;
  autenticación fallida → `sealed_payload_auth_failed` (un solo código,
  sin oráculo).
- **`export-result-v2`** expone `bundle_id` + `manifest_sha256` como
  anclas manuales anti re-sellado (el sello da integridad bajo una
  clave, no atestación de origen).
- **Matriz de pruebas §9 del ADR** consolidada fila por fila
  (`tests/test_sealed_matrix.py`), suite verde con el extra y sin él
  (skips honestos); `scripts/gate_sealed_adapter.py` — adaptador
  determinístico sólo para gates, excluido del wheel. Guía de uso:
  [`docs/sealed-export-guide.md`](../sealed-export-guide.md).

## Compatibilidad y límites

- Actualización directa desde beta.17 sin migración física ni cambio de
  contexto gestionado (verificado por `check_beta17_upgrade.py`: camino
  `export/v1` intacto tras upgrade — create/verify/restore en claro —
  y `--seal` end-to-end con el adaptador determinístico: create v2,
  verify sin clave honesto, verify con clave `verified: true`, restore
  sellado).
- **Sin rupturas deliberadas**: bundles v1 existentes siguen
  verificando y restaurando; la compactación sigue leyendo sólo v1 (un
  bundle sellado como insumo se rechaza: sellado es respaldo, no insumo
  de compactación).
- **Fugas residuales declaradas (ADR-0042 §7)**: el manifiesto v2 va en
  claro y revela metadatos de composición del store (conteos, tamaños,
  categorías de objetos, estructura relativa, patrón de actividad) —
  precio de la verificación estructural sin clave. El bundle sellado no
  es byte-reproducible (CEK aleatoria por diseño); lo preservado y
  probado es el store restaurado byte-idéntico.
- Warnings sin cruce por perfil: v1 conserva
  `plaintext_export_contains_untrusted_memory_data`; sellado emite
  `sealed_export_untrusted_memory_data`; verify sin clave
  `sealed_payloads_unverified_without_key`.
- Python 3.9+; sin dependencias de runtime nuevas (el extra es
  opcional). GitHub Actions sigue sin ejecutarse por facturación: CI
  local es el gate documentado.

## Instalar o actualizar

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.18"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . verify
```

La versión esperada es `an-kla-memory 0.1.0b18`; `context status`
conserva `template_version: "0.1.0-beta.11"`.

Para respaldos sellados, instala el extra opcional:

```bash
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory[sealed] @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.18"
```

(`cryptography>=42`; sin él, todo comando sellado falla cerrado con
`sealing_extra_not_installed` — nunca degrada a claro.)
