# Ronda adversarial — `v0.1.0-beta.17` (2026-08-20)

Candidata construida en la rama `release/beta.17` desde `main` (`916c146`,
PRs #90/#91 + fix `0cea150` ya fusionados). Ronda integral de release. La
etiqueta se crea sobre el árbol exacto que este documento describe.

## Alcance

Contenido: adopción explícita de baseline (ADR-0040, cierra ADR-0035/#45),
inventario físico (ADR-0041/#68), refactor del parser CLI. Ruptura
deliberada documentada: `context update`/`install` fail-closed ante drift
no adoptado. Cada pieza con proceso propio completo (spike → ADR → rondas
pre-code y post-code pre-commit, verificados por revisores independientes
con ejecución real: `docs/planning/issue-45-{spike,implementation}-*.md`,
`issue-68-{spike,implementation}-*.md`). Esta ronda audita el conjunto
como candidata publicable.

## Modelo de amenazas

Riesgos del conjunto: (1) el fail-closed de update podía matar el flujo
ADR-0017 — cerrado con carve-out y test de regresión (hallazgo crítico de
la ronda pre-code de #45); (2) la adopción podía blanquear contratos
corruptos — cerrado por validación semántica (enmienda v2 por dogfooding:
hash huérfano legítimo aceptado, contrato a mano nunca); (3) el inventario
podía servir revisiones archivadas — cerrado con catalog-first verificado
contra la ventana `committed_cleanup_incomplete` real; (4) invariante de
counts — bucket `eliminada` por decisión del maintainer, colisión `total`
tratada como exótica. La memoria recuperada sigue siendo dato no confiable.
