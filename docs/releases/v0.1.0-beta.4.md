# AN-KLA Memory v0.1.0-beta.4

Versión del código: `0.1.0b4`. Etiqueta de distribución: `v0.1.0-beta.4`.

## Resumen

Release centrado en cerrar los issues #10 (recall de recuperación) y #11
(texto canónico del contrato), más la adición de un hook opcional y
no bloqueante de verificación de versiones.

## Cambios de comportamiento

### Recuperación multi-stream (issue #10)

- `retrieve` y `assemble-context` ya no ignoran `events` ni `episodes`. El
  parámetro `streams` (default `("facts",)`) selecciona los streams a
  recorrer, preservando el contrato histórico de la beta.
- Nuevo flag CLI `--streams facts,episodes` en `retrieve`.
- `build_index` ahora indexa los tres streams (`facts_fts`, `events_fts`,
  `episodes_fts`). El índice SQLite lleva `index_version = "2"` y
  `schema: an-kla/index-v2`; los índices v1 se reportan como `index_obsolete`
  y degradan a scan.
- Tras `commit-write-plan`, el motor refresca el índice FTS5 para la nueva
  revisión **fuera del lock de escritura**, en best-effort. Ya no se requiere
  `rebuild-index` manual después de cada commit.

### Transparencia en exclusiones (issue #10)

- `retrieve` ahora expone `excluded_detail.ids` (truncado a 50 IDs por razón)
  y `excluded_detail.truncated` para `inactive`, `zero_score`, `budget`,
  `no_text` e `invalid_record`. `excluded_summary` se mantiene por
  compatibilidad.

### Texto canónico del contrato (issue #11)

- Nuevo subcomando `context show-template [--version <tag>]` devuelve el texto
  canónico del bloque administrado y del contrato detallado de la versión
  instalada, y los hashes de plantillas históricas conocidas.

### Hook opcional de verificación de versiones (ADR-0012)

- Al iniciar, el CLI consulta (sólo lectura) la release más reciente de
  `api.github.com/repos/kristhianmanue1/an-kla-memory/releases/latest`,
  cachea 24 h en `~/.cache/an-kla/update-check.json` (XDG-aware) y, si hay
  versión más reciente, imprime el aviso a **stderr**.
- Omisión automática con `CI`, `GITHUB_ACTIONS`, `AN_KLA_DISABLE_UPDATE_CHECK`,
  `AN_KLA_NO_UPDATE_CHECK=1`. Flag `--no-update-check` por invocación.
- Subcomando explícito `check-updates` para forzar la consulta.
- **AN-KLA no ejecuta pip ni se reemplaza a sí mismo.** El aviso es
  informativo; el operador decide.
- `capabilities()` añade el bloque `update_check` declarando source, canal,
  TTL, opt-out y `install_or_self_replace: false`.

## Cambios de contrato

- `TEMPLATE_VERSION = "0.1.0-beta.4"`. `content_sha256` sin cambios;
  `contract_sha256` cambia por la nueva sección "## Verificación no
  bloqueante de versiones" en `DETAILED_CONTRACT`.
- `0.1.0-beta.3` registrada en `_KNOWN_CONTEXT_TEMPLATES`.

## Cambios de schema

- `an-kla/retrieval-result-v1`: campos nuevos (additivos) `streams_searched`,
  `selected[i].stream`, `excluded_detail.{ids,truncated,cap}`.
- Índice SQLite: `schema = an-kla/index-v2`, `index_version = 2`. Los índices
  v1 se rechazan con `index_obsolete`.

## Migración desde beta.3

```bash
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.4"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . context status
.venv/bin/python -m an_kla --project-root . upgrade inspect \
  --target v0.1.0-beta.4 > /tmp/plan.json
.venv/bin/python -m an_kla --project-root . upgrade apply \
  "$(jq -r .plan_fingerprint /tmp/plan.json)" --plan /tmp/plan.json
.venv/bin/python -m an_kla --project-root . upgrade verify --target v0.1.0-beta.4
.venv/bin/python -m an_kla --project-root . rebuild-index
git diff -- AGENTS.md AN-KLA.md
```

## Límites no resueltos

- El hook update-check permanece silencioso (`fetch_failed`) mientras el repo
  sea privado. La lógica está lista para cuando la visibilidad cambie.
- Auto-reindex es best-effort: si el primer commit ocurre antes de cualquier
  `rebuild-index` explícito (padre sin índice), no se construye.
- `supersede`, `refute`, `decay` siguen sin operación gobernada.
