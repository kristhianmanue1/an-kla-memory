# `v0.1.0-beta.16`

Beta.16 publica lo acumulado en `main` tras beta.15 (PRs #85, #86, #88):
denominadores de frescura, ligadura de checkpoints a Git, contrato
observable de integración, señal de contexto en `init` y ayuda CLI
completa.

El contexto gestionado y la plantilla administrada permanecen en
`0.1.0-beta.11`. Esta release no cambia almacenamiento físico, política
de autoridad ni el contrato `plan-write → commit-write-plan`.

## Cambios principales

- **Denominadores de frescura (G-FRESH, ADR-0037, #50)**: el bloque
  `freshness` de `retrieve`/`assemble-context`/MCP declara
  `evaluated/not_evaluable/unparseable/stale` sobre la población final
  servida, con el invariante `evaluated + not_evaluable + unparseable =
  |seleccionados|`. "Nada desfasado" deja de ser indistinguible de "nada
  era evaluable"; el denominador de `view context` queda diferido con
  test que impide añadirlo por accidente.
- **`source_state` perfil `git/v1` (ADR-0038, #79)**: los checkpoints
  pueden ligarse al commit que describen (`head` object-id completo,
  `branch`, `dirty_digest`), todos `caller_asserted`: el caller observa
  Git y declara; el CLI no ejecuta Git ni acuña autoridad. Supersede
  normativo del nombre registrado (reserva de ADR-0023/ADR-0030 §4).
- **`integration status` (G1, ADR-0039, #55)**: contrato observable
  read-only de la integración por ejes independientes (store re-expone
  ADR-0036; contexto gestionado; modo de integración con
  `agent_binding=unverified` y `sharing_boundary=filesystem-access/
  unverified`). Sin enum compuesto.
- **`init` señala el contexto (#87, ADR-0020 v3)**: el resultado incluye
  `context_diagnostics`; un `init` limpio ya no esconde
  `installed: false`.
- **Ayuda CLI completa**: los 29 comandos de primer nivel y los flags
  clave documentados; superficies mutantes marcadas (`repair-durability`
  → MUTATIVO). Guard con test que exige fila propia por comando.
- **Documentación**: deriva factual corregida, features nuevas
  documentadas en README, `CHANGELOG.md` índice, plan 2026-08-20 y sus
  16 rondas adversariales indexados.

## Compatibilidad y límites

- Actualización directa desde beta.15 sin migración física ni cambio de
  contexto gestionado (verificado por `check_beta15_upgrade.py`).
- El sobre mínimo de payloads v2 con frescura creció (~58 B): costo del
  contrato, declarado en ADR-0037 y fijado en test.
- Checkpoints con `git/v1` exigen un binario ≥ beta.16 (evolución
  unidireccional, documentada).
- G2–G4 (#56–#58) permanecen como diseños de entrada; nada de esta
  release los implementa.
- Python 3.9 o posterior; sin dependencias de runtime. GitHub Actions
  sigue sin ejecutarse por facturación: CI local es el gate documentado.

## Instalar o actualizar

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.16"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . integration status
.venv/bin/python -m an_kla --project-root . verify
```

La versión esperada es `an-kla-memory 0.1.0b16`; `context status`
conserva `template_version: "0.1.0-beta.11"`.
