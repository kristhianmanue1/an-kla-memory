# AN-KLA Memory v0.1.0-beta.2

Fecha: 2026-08-03

## Propósito

Esta beta convierte contratos que antes exigían leer el checkout en una
superficie pública, determinista y consumible por agentes. No cambia el formato
físico de memoria ni amplía la autoridad de escritura.

## Cambios principales

- Añade `an-kla capabilities`, una descripción JSON canónica de capacidades,
  límites, perfiles de recuperación, política de escritura y herramientas MCP.
- Declara de forma legible por máquina que recuperación v1 busca sólo `facts`,
  que MCP permanece de sólo lectura y que el costo implementado usa bytes
  UTF-8, no tokens exactos.
- Añade `an-kla schema list` y `an-kla schema show <name>` con errores estables.
- Empaqueta los cinco JSON Schema normativos: propuesta, autoridad, decisión,
  plan de escritura y certificado de costo.
- Garantiza por pruebas que los schemas del wheel son idénticos a sus fuentes
  normativas en `docs/schemas/`.
- Añade una API Python de sólo lectura para capacidades y recursos de schema.
- Documenta la arquitectura agent-first y un plan técnico posterior a la
  revisión crítica del reporte de Argos.

## Compatibilidad

- El formato físico definido por ADR-0001 permanece sin cambios.
- Las envolventes presupuestadas v1 conservan campos, serialización, ranking y
  selección; las capacidades se exponen en un comando separado.
- La plantilla administrada de contexto sigue siendo `0.1.0-beta.1`, porque su
  contenido no cambió en esta entrega.
- La instalación soporta Python 3.9 o posterior y no agrega dependencias de
  ejecución.

## Verificación

La publicación exige:

- suite completa de pruebas;
- comprobación de metadatos contra `v0.1.0-beta.2`;
- construcción e inspección del wheel;
- instalación aislada sin checkout;
- ejecución aislada de `--version`, `capabilities`, `schema list` y
  `schema show` sin crear `.an-kla`.

## Límites

- La recuperación v1 continúa limitada al stream `facts`.
- No hay recuperación multi-stream ni explicación por candidato.
- No se garantizan tokens BPE ni framing exacto de un proveedor.
- MCP continúa de sólo lectura.
- La coordinación de escritura es local, no multi-máquina.
- No hay compactación ni recolección de basura.
