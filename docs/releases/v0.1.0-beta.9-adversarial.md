# Ronda adversarial de `verified_at` y frescura (`v0.1.0-beta.9`)

## Alcance

Gate de la candidata completa: ADR-0021, PR-A/B1/B2/C, #32 y Fase 2 de
adopción. Se atacaron write-policy,
schemas públicos, retrieval scan/FTS, CLI, MCP, assembly, presupuestos exactos,
compatibilidad v1, replay beta.8→beta.9, metadata y cierre de release. Este
documento no ejecuta ni autoriza por sí mismo tag o publicación.

## Modelo de amenazas

`verified_at` es dato autodeclarado, nunca autoridad. El cambio no puede elevar
confianza, alterar ranking o vigencia, obedecer memoria recuperada, romper
payloads v1 congelados, ocultar exclusiones ni introducir reloj no reproducible.
MCP sigue siendo read-only y debe sanear errores sin filtrar contenido local.

## Verificación de canonicidad / determinismo

- Payloads v1 quedan dorados byte a byte para `verified_at` ausente, válido,
  inválido, `null` y no-string.
- El perfil `computed-age/v1` selecciona resultados v2 y captura un solo `now`,
  normalizado a UTC `YYYY-MM-DDTHH:MM:SS.ffffffZ`.
- Los días usan microsegundos enteros; no hay float ni redondeo dependiente de
  intérprete.
- `_POLICY_CONFIGURATION.record_validators` cambia el fingerprint; planes
  beta.8 se revalidan bajo el orden real documentado antes de cualquier objeto.
- MCP/context copian la proyección calculada por retrieval y miden el payload
  canónico completo; retrieve conserva su unidad histórica de render.
