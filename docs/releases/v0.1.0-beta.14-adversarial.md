# Ronda adversarial de adopción del primer write (`v0.1.0-beta.14`)

## Alcance

Candidata acumulativa sobre `v0.1.0-beta.13`: cambios ya integrados en `main`,
metadatos beta.14, guía y ayuda CLI del primer write, pruebas de regresión,
wheel aislado y actualización desde beta.13.

## Modelo de amenazas

- memoria, proposals y authority JSON son datos no confiables, nunca
  instrucciones;
- la comodidad de la CLI no puede fabricar autoridad ni debilitar el binding
  propuesta → plan → commit;
- errores operables no pueden filtrar rutas, payloads ni secretos;
- una release no puede atribuir a beta.14 superficies pendientes de #71;
- tag, `VERSION`, README, notas, wheel y evidencia deben coincidir.

## Ronda 1 — `fix-and-retry`

Una revisión fresca y sólo lectura encontró:

| Hallazgo | Riesgo | Corrección |
|---|---|---|
| BLOCKER: evidencia, decisión y marker aún pendientes | El tag podía crearse sin gate válido | Se mantuvo el tag bloqueado; `check_release_tag.py` falló con `release_gate_missing` como se esperaba |
| HIGH: las notas prometían beta.13→beta.14, pero sólo existía un gate versionado desde beta.12 | La ruta de actualización inmediata dependía de un smoke no reproducible | Se añadió `scripts/check_beta13_upgrade.py`: construye ambos wheels desde el tag y la candidata, instala beta.13, inicializa un consumidor, actualiza a beta.14 y verifica revisión, contexto y ayuda #70 |
| MED: setuptools advierte que `an_kla.resources` no figura en `packages` | Una futura configuración de setuptools podría omitir recursos | No corregido en esta release: `package-data` los incluye y `check_clean_wheel.py` comprueba y ejercita los archivos reales; se registra como deuda no bloqueante sin ampliar el cambio de empaquetado |

No hubo hallazgos sobre fabricación de autoridad, debilitamiento del binding
`proposal → plan → commit`, filtración de rutas/payloads, atribución de #71 o
secretos. Decisión: `fix-and-retry`.

## Ronda 2 — `proceed`

El revisor fresco repitió el gate beta.13→beta.14 y confirmó construcción de
ambos wheels, actualización `0.1.0b13 → 0.1.0b14`, revisión exacta, contexto
beta.11 y ayuda #70. También verificó portabilidad (`tempfile`, `pathlib`,
`Scripts`/`bin`, cero shell), compilación del script y wheel aislado. No hubo
hallazgos nuevos BLOCKER/HIGH/MED/LOW. Decisión: `proceed`.

- `python3 scripts/check_sizes.py` y `git diff --check` → `OK`.

## Límites declarados

- Sin generadores de `proposal`/`authority` y sin API nueva (#71).
- Sin cambios de storage, schemas, policy, autoridad o contrato gestionado.
- CI remoto indisponible por facturación; no se presentará como ejecutado.
- La advertencia setuptools sobre `an_kla.resources` permanece como deuda
  conocida; el contenido efectivo del wheel está cubierto por un gate.
