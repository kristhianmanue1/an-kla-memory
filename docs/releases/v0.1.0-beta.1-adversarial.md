# Ronda adversarial de `context-package/v1`

## Alcance

La ronda atacó la implementación candidata de `v0.1.0-beta.1` antes de su
publicación. Se revisaron por separado el núcleo de transformación, los límites
de propiedad, el filesystem, la concurrencia, el CLI y las instrucciones que el
agente recibe.

## Hallazgos y correcciones

| Hallazgo | Riesgo | Corrección |
|---|---|---|
| El manifiesto trataba cualquier cambio exterior como corrupción. | AN-KLA interfería con reglas legítimas añadidas por el usuario. | La deriva exterior es advertencia; el hash del bloque sigue siendo la compuerta vinculante. |
| `uninstall` podía borrar un `AN-KLA.md` preexistente idéntico. | Pérdida de archivo que AN-KLA no creó. | El manifiesto conserva propiedad independiente del contrato y sólo elimina archivos creados por el instalador. |
| Un `AGENTS.md` preexistente vacío podía eliminarse. | Confundir contenido vacío con propiedad de AN-KLA. | El archivo se conserva salvo evidencia local de creación por el instalador. |
| Un manifiesto único aceptaba destinos anidados. | La segunda instalación sobrescribía la trazabilidad de la primera. | `context-package/v1` queda limitado al `AGENTS.md` raíz. |
| Un padre `.an-kla` simbólico podía redirigir manifiesto o respaldos. | Escritura fuera de la raíz declarada. | Se rechaza cualquier enlace simbólico en la ruta administrada. |
| El plan no ligaba el manifiesto observado. | Una modificación entre plan y apply podía alterar propiedad o desinstalación. | `base_manifest_sha256` forma parte del plan reconstruido bajo lock. |
| Un fallo entre contrato, bloque y manifiesto podía quedar sin diagnóstico específico. | Instalación parcial difícil de interpretar. | `status` informa contrato huérfano, bloque ausente, manifiesto ausente o deriva, según el punto de interrupción. |
| El contrato decía resolver un intérprete, pero los ejemplos fijaban `python3`. | El agente podía ignorar el entorno Python 3.12 del proyecto. | Se declara que `python3` es un marcador operativo y se prefiere `.venv/bin/python`. |
| El contrato no cerraba la fabricación de autoridad privilegiada. | Un agente podía intentar autodeclarar confirmación o evidencia de herramienta. | Se prohíbe fabricar `tool_observed` o `channel_confirmed` y se exige adaptador externo. |

## Ataques que deben permanecer verdes

- archivo inexistente, existente, vacío, LF y CRLF;
- idempotencia sin cambio de `mtime`;
- actualización de plantilla vieja con payload íntegro;
- preservación de prefijo y sufijo; preservación de bits de modo en POSIX;
- edición del bloque, contrato y manifiesto;
- marcadores duplicados, anidados, incompletos, indentados o dentro de fences;
- plan alterado y cambio concurrente de destino o manifiesto;
- lock ocupado;
- destino no UTF-8, directorio, ruta absoluta, traversal y enlace simbólico;
- `.an-kla` simbólico;
- instalación limpia sin manifiesto local;
- desinstalación de archivo propio y conservación de archivos preexistentes;
- detección de integración alfa real en
  `/Users/krisnova/www/test_an-kla_01/AGENTS.md` sin modificarla.

## Resultado

La suite especializada cubre 26 casos y la suite total 117 pruebas en Python
3.9 y Python 3.12. La comprobación del tag esperado
`v0.1.0-beta.1 -> 0.1.0b1` y `git diff --check` pasan.

La integración alfa real termina con
`legacy_an_kla_context_detected`; por tanto no se añade silenciosamente un
bloque que contradiga su instrucción heredada de usar `write`.

## Límites residuales aceptados

- El lock sólo coordina procesos cooperativos de la misma máquina.
- Cada archivo se sustituye atómicamente, pero contrato, bloque y manifiesto no
  forman una transacción atómica multiarchivo; `status` hace visible un estado
  parcial y una ejecución posterior puede repararlo.
- SHA-256 detecta deriva accidental, no autoría: quien puede editar el archivo
  puede recalcular la huella.
- No hay fusión automática de texto legado ni de un bloque modificado.
- Adaptadores de proveedor y `AGENTS.md` anidados quedan fuera de esta beta.
