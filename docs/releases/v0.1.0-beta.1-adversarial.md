# Ronda adversarial de `context-package/v1`

## Alcance

La ronda atacó la implementación candidata de `v0.1.0-beta.1` antes de su
publicación. Se revisaron por separado el núcleo de transformación, los límites
de propiedad, el filesystem, la concurrencia, el CLI y las instrucciones que el
agente recibe.

La segunda pasada contrastó el contrato con fuentes primarias sobre instrucciones
para agentes, prompt injection, consentimiento de herramientas y procedencia:

- OpenAI, [Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/):
  alcance y precedencia de `AGENTS.md`;
- OpenAI, [Harness engineering](https://openai.com/index/harness-engineering/):
  el archivo raíz funciona como mapa breve hacia conocimiento versionado;
- OpenAI, [Understanding prompt injections](https://openai.com/safety/prompt-injections/)
  y [Designing agents to resist prompt injection](https://openai.com/index/designing-agents-to-resist-prompt-injection/):
  acceso mínimo, instrucciones explícitas, confirmación y defensa en profundidad;
- GitHub, [Writing effective custom instructions](https://docs.github.com/en/enterprise-cloud@latest/copilot/tutorials/customize-code-review):
  instrucciones breves, específicas y separadas por alcance;
- MCP, [Security and Trust & Safety](https://modelcontextprotocol.io/specification/2025-03-26/index):
  consentimiento del usuario y anotaciones de herramientas tratadas como no
  confiables salvo servidor confiable;
- NIST, [AI RMF Generative AI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf):
  trazabilidad de procedencia y evaluación contra evidencia conocida.

Estas fuentes orientan el threat model; no se presentan como prueba de que un
texto de instrucciones elimine por sí mismo prompt injection.

## Hallazgos y correcciones

| Hallazgo | Riesgo | Corrección |
|---|---|---|
| El manifiesto trataba cualquier cambio exterior como corrupción. | AN-KLA interfería con reglas legítimas añadidas por el usuario. | La deriva exterior es advertencia; el hash del bloque sigue siendo la compuerta vinculante. |
| `uninstall` podía borrar un `AN-KLA.md` preexistente idéntico. | Pérdida de archivo que AN-KLA no creó. | El manifiesto conserva propiedad independiente del contrato y sólo elimina archivos creados por el instalador. |
| Un `AGENTS.md` preexistente vacío podía eliminarse. | Confundir contenido vacío con propiedad de AN-KLA. | El archivo se conserva salvo evidencia local de creación por el instalador. |
| Un manifiesto único aceptaba destinos anidados. | La segunda instalación sobrescribía la trazabilidad de la primera. | `context-package/v1` queda limitado al `AGENTS.md` raíz. |
| Un padre `.an-kla` simbólico podía redirigir manifiesto o respaldos. | Escritura fuera de la raíz declarada. | Se rechaza cualquier enlace simbólico en la ruta administrada. |
| El plan no ligaba el manifiesto observado. | Una modificación entre plan y apply podía alterar propiedad o desinstalación. | `base_manifest_sha256` forma parte del plan reconstruido bajo lock. |
| Un fallo entre contrato, bloque y manifiesto podía quedar sin diagnóstico específico. | Instalación parcial difícil de interpretar. | `status` informa contrato huérfano, bloque ausente, manifiesto ausente o deriva, según el punto de interrupción. |
| El contrato decía resolver un intérprete, pero los ejemplos fijaban `python3`. | El agente podía ignorar el entorno Python 3.12 del proyecto. | Se declara que `python3` es un marcador operativo y se prefiere `.venv/bin/python`. |
| El contrato no cerraba la fabricación de autoridad privilegiada. | Un agente podía intentar autodeclarar confirmación o evidencia de herramienta. | Se prohíbe fabricar `tool_observed` o `channel_confirmed` y se exige adaptador externo. |
| Git materializa Markdown con CRLF en Windows. | Un contrato semánticamente idéntico se declaraba modificado. | Verificación canónica LF con CAS sobre bytes físicos y preservación del estilo existente. |
| La propuesta documental leía `.an-kla/memory/working-state.json`. | Esa ruta pertenece a la investigación, no al almacén content-addressed del producto. | La retoma usa exclusivamente `status`, `verify` y `assemble-context`. |
| El agente confiaba en `AN-KLA.md` antes de comprobar su manifiesto. | Un contrato alterado podía reintroducir instrucciones inseguras. | `context status` es preflight y la deriva no se repara automáticamente. |
| `write-summary` se describía como resumen verificado. | La política liga hashes, pero no evalúa fidelidad ni compresión semántica. | El contrato limita la garantía y exige contraste con evidencia y linaje visible. |
| El cierre exigía actualizar el checkpoint. | `commit_write_plan()` usa un parche vacío y la única ruta con parche es heredada. | Se expone `governed_checkpoint_update_unavailable` y se prohíbe el fallback silencioso. |
| No existía una compuerta explícita de minimización. | Secretos o datos personales podían persistirse con procedencia válida. | Se prohíben credenciales y se prefieren hashes, referencias y resultados saneados. |
| La redirección a `planning-result.json` podía sobrescribir o filtrar datos. | Colisión entre agentes, pérdida local o inclusión accidental en Git. | El contrato exige un artefacto efímero nuevo, privado y no rastreado. |
| Una instalación previa limpia no podía actualizarse sin su manifiesto gitignored. | Un clon nuevo quedaba bloqueado o tentaba al operador a sobrescribir manualmente. | Un registro empacado de huellas anteriores reconoce sólo el par bloque/contrato canónico y permite la migración segura. |
| `update` cambiaba el bloque pero no el contrato referenciado. | El agente recibía instrucciones de una versión distinta a la declarada por el marcador. | El plan y el apply ligan y sustituyen ambos artefactos; el contrato anterior se respalda por contenido. |
| El README empezaba en `init` sin instalar ni verificar una versión. | Un consumidor no sabía distinguir paquete, memoria e integración de contexto. | Se documentan venv, etiqueta exacta, `--version`, instalación, actualización, retiro y comprobaciones posteriores. |

## Ataques que deben permanecer verdes

- archivo inexistente, existente, vacío, LF y CRLF;
- idempotencia sin cambio de `mtime`;
- actualización de plantilla vieja con payload y contrato íntegros, sin
  manifiesto local y bajo LF o CRLF;
- negativa a actualizar un contrato anterior localmente modificado;
- preservación de prefijo y sufijo; preservación de bits de modo en POSIX;
- edición del bloque, contrato y manifiesto;
- marcadores duplicados, anidados, incompletos, indentados o dentro de fences;
- plan alterado y cambio concurrente de destino o manifiesto;
- lock ocupado;
- destino no UTF-8, directorio, ruta absoluta, traversal y enlace simbólico;
- `.an-kla` simbólico;
- instalación limpia sin manifiesto local;
- desinstalación de archivo propio y conservación de archivos preexistentes;
- detección de integración alfa real en
  `/Users/krisnova/www/test_an-kla_01/AGENTS.md` sin modificarla.
- contrato sin rutas internas falsas, sin `write-decay` y con límites de
  summary, checkpoint, autoridad, privacidad y coordinación visibles.

## Resultado

La suite especializada cubre 31 casos y la suite total 124 pruebas en Python
3.9 y Python 3.12. La comprobación del tag esperado
`v0.1.0-beta.1 -> 0.1.0b1` y `git diff --check` pasan.

La integración alfa real termina con
`legacy_an_kla_context_detected`; por tanto no se añade silenciosamente un
bloque que contradiga su instrucción heredada de usar `write`.

## Límites residuales aceptados

- El lock sólo coordina procesos cooperativos de la misma máquina.
- Cada archivo se sustituye atómicamente, pero contrato, bloque y manifiesto no
  forman una transacción atómica multiarchivo; `status` hace visible un estado
  parcial y una ejecución posterior puede repararlo.
- SHA-256 detecta deriva accidental, no autoría: quien puede editar el archivo
  puede recalcular la huella.
- No hay fusión automática de texto legado ni de un bloque modificado.
- Adaptadores de proveedor y `AGENTS.md` anidados quedan fuera de esta beta.
