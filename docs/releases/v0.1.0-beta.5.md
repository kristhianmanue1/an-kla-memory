# AN-KLA Memory v0.1.0-beta.5

Versión del código: `0.1.0b5`. Etiqueta de distribución: `v0.1.0-beta.5`.

## Resumen

Release centrado en cerrar el issue #12 (transparencia de target drift en
upgrade flow, ADR-0017) y decidir el issue #14 con opción C (campo explícito
`indexable_text`, ADR-0018).

## Cambios de comportamiento

### Transparencia de target drift (issue #12, ADR-0017)

Antes, `upgrade apply` absorbía silenciosamente cualquier edición fuera del
bloque gestionado en `AGENTS.md`, normalizando la baseline sin dejar huella.
Ahora:

- `upgrade inspect` expone `core.target_drift` con cinco campos:
  `outside_managed_block`, `manifest_target_sha256_at_install`,
  `observed_target_sha256`, `managed_content_sha256`, `will_be_absorbed_by_apply`.
- `upgrade apply` falla cerrado con `target_drift_requires_confirmation`
  cuando hay drift y no se pasa el flag `--confirm-target-drift`.
- `apply` exitoso declara `warnings: ["target_drift_absorbed_into_new_baseline"]`
  y `target_drift` completo en el resultado.
- Schema bump: `an-kla/upgrade-plan-v1` → `an-kla/upgrade-plan-v2`
  (backwards compatible: `_validate_plan` acepta ambos).
- Sección nueva en el *Protocolo de actualización* de `AN-KLA.md`.

### Campo explícito `indexable_text` (issue #14 opción C, ADR-0018)

`record_text()` ahora prioriza `indexable_text > text > render > summary > p`.
Los records estructurados (events/episodes con `outcome`, `lessons`, `type`)
pueden llevar `payload.indexable_text` (o `record.indexable_text`) para ser
indexados por FTS sin requerir un campo `text` natural.

## Cambios de contrato

- `TEMPLATE_VERSION = "0.1.0-beta.5"`. `content_sha256` sin cambios;
  `contract_sha256` cambia por la nueva sección del *Protocolo de actualización*.
- `0.1.0-beta.4` registrada en `_KNOWN_CONTEXT_TEMPLATES`.

## Cambios de schema

- Nuevo `an-kla/upgrade-plan-v2` (campo aditivo `target_drift` en `core`).
- `an-kla/upgrade-plan-v1` queda aceptado por `_validate_plan` pero los nuevos
  planes usan v2.

## Migración desde beta.4

```bash
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.5"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . context status
.venv/bin/python -m an_kla --project-root . upgrade inspect \
  --target v0.1.0-beta.5 > /tmp/plan.json
# Si el plan reporta target_drift.outside_managed_block: true, revisa el diff
# AGENTS.md antes de confirmar.
.venv/bin/python -m an_kla --project-root . upgrade apply \
  "$(jq -r .plan_fingerprint /tmp/plan.json)" --plan /tmp/plan.json \
  --confirm-target-drift
.venv/bin/python -m an_kla --project-root . upgrade verify --target v0.1.0-beta.5
.venv/bin/python -m an_kla --project-root . rebuild-index
git diff -- AGENTS.md AN-KLA.md
```

Si no hay drift, `--confirm-target-drift` se ignora sin efecto.
