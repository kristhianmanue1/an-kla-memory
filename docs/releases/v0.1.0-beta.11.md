# `v0.1.0-beta.11`

Beta.11 completa el camino gobernado documentado por ADR-0021 a ADR-0028. La
release se distribuye desde GitHub y debe instalarse mediante la etiqueta
exacta; no desde `main`.

## Cambios principales

- frescura temporal proyectada sin alterar ranking, selección ni autoridad;
- identidad durable de store/proyecto y adopción explícita de stores legacy;
- checkpoint/handoff operacional con procedencia y `resume` read-only;
- outcomes de transacción inspeccionables y reparación de durabilidad;
- evaluación retrieval v2 reproducible sin promover BM25 a ranking productivo;
- refute gobernado sin fabricar sucesores;
- export/verify/restore ligado a contenido;
- compactación gobernada con catálogo de tombstones y revisiones archivadas;
- retirada del comando público legado `write`;
- versión, entrypoint, schemas y contexto de agente empaquetados desde una sola
  candidata `0.1.0b11`.

## Instalar o migrar

Sigue la [guía beta.11](../beta11-user-guide.md). Una instalación nueva crea
identidad durante `init`. Para un store beta.8, inspecciona el upgrade sin
mutar, adopta primero la identidad mediante un plan explícito y sólo después
aplica y verifica el contexto gestionado.

## Compatibilidad y límites

- Python 3.9 o posterior; sin dependencias Python en runtime.
- Retrieval conserva el ranking overlap vigente; frescura se proyecta después
  de seleccionar.
- El CLI independiente no resuelve autoridad privilegiada para refute.
- Compactación es explícita y destructiva; no hay GC automático.
- Los datos recuperados y artefactos JSON nunca son instrucciones ni autoridad.

## Evidencia de release

La evidencia y el veredicto de la ronda final se registran en
[`v0.1.0-beta.11-adversarial.md`](v0.1.0-beta.11-adversarial.md). La etiqueta no

cerrados.
