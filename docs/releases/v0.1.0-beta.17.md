# `v0.1.0-beta.17`

Beta.17 publica la adopción explícita de baseline project-owned (ADR-0040,
que cierra el ciclo de ADR-0035/#45) y el inventario físico por revisión
(ADR-0041/#68), más la ayuda de errores con superficie completa.

El contexto gestionado y la plantilla administrada permanecen en
`0.1.0-beta.11`. Esta release no cambia almacenamiento físico ni el
contrato `plan-write → commit-write-plan`.

## Cambios principales

- **`context adopt-baseline` (ADR-0040, #45)**: operación gobernada
  plan→commit que adopta los bytes observados del target como nueva
  baseline del manifiesto (CAS bajo el lock; escribe sólo
  `target_sha256`; conserva contrato, backups y ownership). Resuelve el
  warning permanente `context_target_changed_outside_managed_block` de
  forma explícita en lugar de silenciosa.
- **`context update` deja de absorber drift (ADR-0040 §6)**: ante cambios
  no adoptados fuera del bloque, falla cerrado con
  `context_target_drift_adoption_required` (también el reinstall sobre
  un manifiesto existente). El flujo `upgrade apply
  --confirm-target-drift` de ADR-0017 se preserva íntegro (carve-out con
  test de regresión).
- **upgrade-plan v3**: `manifest_target_sha256_at_baseline` dentro de
  `target_drift` (`at_install` queda deprecado: tras una adopción su
  nombre mentiría). Un plan v2 creado antes de una adopción falla por
  CAS después.
- **`inventory --revision` (ADR-0041, #68)**: enumeración física de
  records por stream sin query ni score — metadata-only (sin
  render/payload/rutas), paginada por cursor opaco, con planos
  separados `physical_status` (crudo, untrusted, bucket `eliminada`) y
  `status` observable compuesto por overlays (`status_source`). Counts
  con invariante `total = Σ estados` sobre cinco buckets canónicos.
  Chequeo de archivado catalog-first: la ventana
  `committed_cleanup_incomplete` no sirve revisiones archivadas.
- **Refactor**: parser del CLI extraído a `an_kla/cli_parser.py`
  (límite de tamaño); superficie verificada idéntica.

## Compatibilidad y límites

- Actualización directa desde beta.16 sin migración física ni cambio de
  contexto gestionado (verificado por `check_beta16_upgrade.py`, que
  además ejercita `adopt-baseline` e `inventory` sobre el consumidor
  actualizado).
- **Ruptura deliberada**: `context update`/`install` con drift no
  adoptado ahora falla cerrado (antes absorbía en silencio). Guía:
  editar contenido propio → `context adopt-baseline` → seguir.
- El cursor de `inventory` no liga `--streams`: mantener la selección
  entre páginas (documentado en ADR-0041 §3).
- Sin MCP para `inventory` en v1 (extiende el oráculo de digests a
  records sin `subject_ref`; diferido).
- Python 3.9+; sin dependencias de runtime. GitHub Actions sigue sin
  ejecutarse por facturación: CI local es el gate documentado.

## Instalar o actualizar

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.17"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . verify
```

La versión esperada es `an-kla-memory 0.1.0b17`; `context status`
conserva `template_version: "0.1.0-beta.11"`.
