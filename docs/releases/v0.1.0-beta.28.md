# v0.1.0-beta.28 — Cierre del backlog táctico (#111 + #133)

Etiqueta: `v0.1.0-beta.28` · Versión: `0.1.0b28` · Base: `780143d`.
**No cambia la plantilla gestionada** (`TEMPLATE_VERSION` sigue en
`0.1.0-beta.26`) ni el contrato de recuperación de beta.27. Añade un schema

## Contenido

### Vocabulario en el diagnóstico de arranque (#133 propuesta 2 — cierra #133)

- `startup-diagnostic-v2` **disperso** (convención ADR-0049): cuando el
  store pudo evaluarse (`store_presence: "present"` y lectura exitosa), el
  diagnóstico añade el eje `vocabulary`:
  - `terms`: términos más frecuentes del stream `facts` (cap 32, orden
    `(-frecuencia documental, término)`, tokenización idéntica a
    retrieval);
  - `ids`: primeros 50 ids de facts activos;
  - `record_count`: total de facts activos.
- Un agente de contexto fresco puede así formular una query con solape
  léxico (y evitar el `empty_reason` de beta.27) sin leer memoria
  directamente. v1 queda byte-idéntica para stores ausentes/ilegibles.
- Distribución completa: schema + whitelist + tupla de contratos + doble
  copia byte docs/paquete + inventario.

### Liveness de compactación (#111/F5 — cierra #111)

- **Problema**: `commit_compaction` adquiría el gate exclusivo (espera
  ≤10 s por lectores) *dentro* de los locks identity+write: durante el
  drenado, toda escritura e identidad quedaban congeladas.
- **Fix**: el gate EX se sondea sin bloquear (`timeout=0`) dentro de los
  locks, con reintentos cada 50 ms y **locks liberados entre intentos**
  (presupuesto total 10 s → `compaction_readers_active` fail-closed).
  Los escritores avanzan durante el drenado (verificado: adquisición del
  write lock en <1 ms con lector sostenido).
- **Ronda adversarial**: el primer intento de fix (reorden ingenuo
  gate→locks) introducía un **deadlock real** con la ruta export/sealed
  (identity→gate SH; reproducido empíricamente por el atacante, F-C3-1).
  El fix definitivo elimina el ciclo estructuralmente (el EX nunca se
  sostiene mientras se espera un lock) y el verificador independiente
  confirmó no-deadlock en 3 escenarios + no-regresión de las rutas
  afectadas (47 tests OK).
- `LockBusyError` es reintentable dentro del presupuesto (F-C4-1).
- F3/F4 (rutas sin fcntl/msvcrt) quedan diferidas con Windows (decisión
  F0 de ADR-0048); F6 registrada como teórica. Con esto, #111 cierra.
