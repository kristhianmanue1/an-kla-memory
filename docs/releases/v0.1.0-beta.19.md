# `v0.1.0-beta.19`

Beta.19 es una release documental: resuelve la deuda C-2 de la ronda REL
de beta.18 (H-5/H-6) y parte ADR-0042 en ADR corto + apéndice técnico
(#95). El runtime no muta respecto de beta.18 salvo el bump de versión;
no hay cambios de almacenamiento, política de autoridad ni del contrato
`plan-write → commit-write-plan`.

El contexto gestionado y la plantilla administrada permanecen en
`0.1.0-beta.11`.

## Cambios principales

- **Deuda C-2 de la REL beta.18** (condición correctiva, ver
  [`v0.1.0-beta.18-adversarial.md`](v0.1.0-beta.18-adversarial.md)):
  - **H-5a**: `CHANGELOG.md` sin doble estado — el bloque «No
    publicadas» que duplicaba el contenido ya sellado de beta.18 se
    retiró; estado único y coherente.
  - **H-5b**: `docs/README.md` cita `v0.1.0-beta.19` como release
    documentada más reciente (antes citaba beta.17).
  - **H-5c**: README coherente con los wheels — la release beta.18 sí
    publicó uno; la frase que lo negaba se corrigió.
  - **H-6**: `scripts/check_clean_wheel.py` pineado a `0.1.0b19` — el
    gate vuelve a ser ejercitable contra la candidata (quedó obsoleto
    en `0.1.0b17` durante el ciclo beta.18).
- **#95 — ADR-0042 partido**: el ADR (622 líneas) pasa a un ADR corto
  (198 líneas: Decisión/Límites/Alternativas) + apéndice técnico en
  [`docs/architecture/refs/sealed-export-v1-appendix.md`](../architecture/refs/sealed-export-v1-appendix.md).
  Las anclas `§1`–`§9` citadas por `an_kla/sealed/*`, schemas y tests
  conservan su numeración; `scripts/check_sizes.py` pasa sin la gracia
  de TECH_DEBT, que se retira.
- **Bump** `0.1.0b18` → `0.1.0b19` (`an_kla/version.py`) con todos los
  metadatos de release sincronizados (README, SECURITY, CITATION,
  CHANGELOG, índice de `docs/`, fixture del update-check).

## Compatibilidad y límites

- **Sin rupturas**: actualización directa desde beta.18 sin migración
  física ni cambio de contexto gestionado; los bundles v1 y sellados
  (v2) existentes siguen verificando y restaurando igual que en
  beta.18.
- **Limitación conocida (deferimiento del operador)**: el soporte de
  Windows permanece diferido — la CI remota de Windows sigue en rojo y
  esta publicación no afirma soporte para esa plataforma; la candidata
  se declara procedible para macOS/Linux. Registrado como límite de la
  release beta.18 en su
  [ronda REL](v0.1.0-beta.18-adversarial.md), §Límites, y heredado por
  esta release mientras el deferimiento siga vigente.
- Python 3.9+; sin dependencias de runtime nuevas. GitHub Actions corre
  con presupuesto limitado: CI local continúa como gate documentado
  complementario.

## Instalar o actualizar

```bash
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.19"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . verify
```

La versión esperada es `an-kla-memory 0.1.0b19`; `context status`
conserva `template_version: "0.1.0-beta.11"`.
