# AN-KLA Memory v0.1.0-alpha.3

Fecha prevista: 2026-08-01

## Propósito

Esta alfa repara compatibilidad de actualización y hace explícita la frontera
entre el recuperador predeterminado y el índice derivado opcional. No migra ni
reescribe revisiones existentes.

## Cambios

- Restaura una extracción textual canónica compartida por índice y recuperación
  con prioridad `text`, `render`, `summary`, `p`.
- Corrige el falso negativo de FTS5 causado por una consulta de sonda con guion.
- Liga cada índice derivado a una referencia `CURRENT` propia de la revisión y
  permite verificación profunda de su hash.
- Conserva `scan-fallback/v1` como perfil predeterminado; `sqlite-fts5/v1` es
  opt-in y degrada explícitamente al escaneo.
- Añade diagnósticos `no_text`, `index_unavailable`, `index_unresolvable` y
  `fts5_unavailable`.
- Corrige la deriva histórica entre los tags `alpha.1`/`alpha.2` y el valor
  `0.1.0a0` que permaneció en `pyproject.toml`. Desde esta entrega la versión de
  paquete y el tag se validan en CI.

## Compatibilidad

La suite incluye un fixture sintético con 22 facts heredados en forma `render`,
18 en forma `payload.text` y uno mixto. La prueba con datos reales se ejecuta en
el repositorio consumidor para evitar copiar memoria privada al producto.

## Límites

- El perfil FTS5 sólo acota candidatos; todavía no usa BM25 como ranking.
- La equivalencia FTS5/scan sólo está probada para tokens ASCII compatibles.
- MCP continúa usando el perfil scan y sigue siendo de sólo lectura.
- El presupuesto global `A(G,W,R,N)` permanece pendiente de
  `context-assembly/v1`.
