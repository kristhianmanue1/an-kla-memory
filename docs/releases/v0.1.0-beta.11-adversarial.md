# Ronda adversarial de evaluación y ciclo de vida (`v0.1.0-beta.11`)

## Alcance

Gate de ADR-0025 y, después, corrección/retención: benchmark v2 sin cambiar
ranking, refute gobernado, export/import verificable, backup/restore y
compactación. Ninguna fase posterior comienza sin cerrar la anterior.

## Modelo de amenazas

Queries, corpus, memoria y summaries son datos no confiables. Una métrica no
prueba verdad, autoridad ni mejora decisional. Un benchmark no puede mutar el
store del operador ni promover un algoritmo por intuición. Retención no puede
borrar historia antes de probar export y restore.

## Implementación ADR-0025 candidata a gate

La implementación local añade evaluación ordenada v2, fixture físico
determinista, cuatro estados de índice, estrategias experimentales aisladas,
schemas empaquetados, CLI y el reporte ligado a digests en
`docs/benchmarks/retrieval-v2-reference-2026-08-08.md`.

Endurecimientos previos a la pasada fresca:

- el schema liga scores enteros a overlap/summary y `float.hex()` a BM25;
- el bundle exige el orden literal overlap→BM25→summary;
- `human_review=pending` exige reviewer null y `passed` exige maintainer;
- `evaluate-v2` general tiene prueba end-to-end con corpus externo y salida
  canónica;
- BM25 no se importa desde retrieval ni autoriza un cambio productivo.
- BM25/summary no se anuncian en `capabilities()`; una regresión impide que
  vuelvan a presentarse como capacidades del producto.

## Gate pre-code ADR-0026

ADR-0026 propone refute como policy separada, sin record sucesor, con autoridad
privilegiada/evidence referenciada, objeto CAS y overlay acumulativo. Estado
tras pre-code r4: `PROCEED`. Se sustituyó autoridad JSON por capability
host + attestation CAS, target ID por selector digest legacy-safe y se cerraron
replay, revision-v2, receipts e inspect en `docs/refute-contract-v1.md`. R4
revalidó todos los hallazgos r1-r3 sin BLOCKER/HIGH y autoriza implementación
local; no autoriza tag/publicación.

## Implementación ADR-0026 candidata a gate

La candidata implementa refute como overlay gobernado sin reescribir segmentos
ni fabricar un record sucesor. La autoridad se resuelve mediante una capability
inyectada por el host, se vuelve a verificar bajo lock y queda ligada a claim,
observations y attestation CAS. El target se publica sólo por digest del record
físico; plan, journal, stage, refutation, revision-v2, receipts e inspect se
validan de extremo a extremo.
