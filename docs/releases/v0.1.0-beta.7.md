# AN-KLA Memory v0.1.0-beta.7

Versión del código: `0.1.0b7`. Etiqueta de distribución: `v0.1.0-beta.7`.
`TEMPLATE_VERSION` sin cambios: `0.1.0-beta.6` (esta release no modifica el
contrato administrado).

## Resumen

Release de **código** centrado en cerrar el issue #15: la vía de escritura
gobernada (`plan-write` / `commit-write-plan`) ahora *señaliza* en el momento
de la decisión que un registro será irrecuperable (`no_text`) antes de que
quede permanente en la memoria. Antes el commit devolvía `committed: true` sin
advertencia y el operador sólo descubría la exclusión al recuperar.

## Cambio de comportamiento

### Señalización de `no_text` en la escritura (issue #15)

Un `record` sin ningún campo indexable (`indexable_text | text | render |
summary | p`) se sigue aceptando (no hay cambio de almacenamiento ni de
política de aceptación), pero la decisión ahora lleva el reason code
`record_without_indexable_text`. La señal fluye por el pipeline existente de
`reason_codes`:

- `evaluate_write()` la añade sólo en decisiones `write-full` / `write-summary`
  (las que efectivamente escriben). Las decisiones `skip` no la llevan.
- `commit-write-plan` la expone en `result.reason_codes`.
- Queda persistida en el evento `write_policy_decision` emitido en la misma
  revisión (huella de auditoría durable).

Motivo: la beta sólo soporta `operation: add` (`supported_operations: ["add"]`),
por lo que un registro `no_text` no puede `supersede`/`refute`/`decay` desde el
CLI; queda inerte de forma permanente. La señalización permite al operador
corregir añadiendo `indexable_text` antes de comprometer la memoria.

### Implementación

- `record_text()` se extrajo a un módulo puro nuevo, `an_kla/record_text.py`,
  para que el núcleo de decisión (`write_policy.py`) pueda reutilizarlo sin
  importar `os`/`sqlite3`/`tempfile` y preservar el invariante de pureza
  (test `test_module_has_no_io_or_nondeterministic_imports`).
  `an_kla/index.py` re-exporta `record_text` para mantener
  `from an_kla.index import record_text` (backward compatible).
- Nuevo reason code `record_without_indexable_text` añadido al catálogo
  fingerprintado de `_POLICY_CONFIGURATION`. Esto cambia `policy_fingerprint()`
  —una evolución de política permitida por ADR-0007— y sólo afecta a escrituras
  nuevas; no se reinterpretan decisiones históricas.
- `capabilities().write_policy` declara `retrieval_requires_indexable_text:
  true` y `no_text_warning_reason_code: "record_without_indexable_text"`. Los
  campos `indexable_text_field` / `indexable_text_priority` siguen viviendo
  bajo `capabilities().retrieval` (sin duplicación).

## Cambios de contrato

- Ninguno. `TEMPLATE_VERSION = "0.1.0-beta.6"`; `content_sha256` y
  `contract_sha256` sin cambios. Quienes ya están en beta.6 pueden actualizar
  sólo el paquete; `context status` seguirá reportando la plantilla beta.6 sin
  drift.

## Cambios de schema

- Ninguno. El reason code viaja por el catálogo de `write-policy/v1`, no
  requiere bump de `an-kla/write-decision-v1` ni `an-kla/write-plan-v1`.

## Migración desde beta.6

Como el contrato administrado no cambia, basta con actualizar el paquete y, si
se desea, re-aplicar el flujo `upgrade` (será un no-op de contexto):

```bash
.venv/bin/python -m pip install --upgrade \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.7"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . context status
.venv/bin/python -m an_kla --project-root . upgrade inspect \
  --target v0.1.0-beta.7 > /tmp/plan.json
.venv/bin/python -m an_kla --project-root . upgrade apply \
  "$(jq -r .plan_fingerprint /tmp/plan.json)" --plan /tmp/plan.json
.venv/bin/python -m an_kla --project-root . upgrade verify --target v0.1.0-beta.7
git diff -- AGENTS.md AN-KLA.md
```

## Tests

- 191 tests OK (187 de beta.6 + 4 nuevos sobre la señalización:
  `test_record_without_indexable_text_is_committed_but_warned`,
  `test_record_with_indexable_text_emits_no_text_warning`,
  `test_skip_decisions_do_not_carry_the_no_text_warning`,
  `test_no_text_warning_flows_through_build_write_plan`).
- Smoke end-to-end del issue #15 verificado: `commit-write-plan` devuelve
  `reason_codes: [..., "record_without_indexable_text", ...]` para un registro
  estructural sin texto; `retrieve` lo excluye como `no_text`. El caso con
  `indexable_text` no advierte.
