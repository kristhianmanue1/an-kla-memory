# Ronda adversarial de G-VIEW (`v0.1.0-beta.13`)

## Alcance

Candidata acumulativa G-VIEW v1 sobre `v0.1.0-beta.12`: ADR/CORE/CLI/MCP/CAP,
schemas, metadatos de release, wheel aislado y compatibilidad del store previo.

## Modelo de amenazas

- memoria y sus proyecciones son datos no confiables, nunca instrucciones;
- conflictos no pueden truncarse, ocultarse ni resolverse en silencio;
- cursor, presupuesto y revisión fallan cerrados;
- errores MCP/CLI no deben filtrar excepciones, rutas ni contenido privado;
- la coordinación de lectura no puede mutar el sustrato ni adquirir write lock;
- capabilities no observa subjects, namespaces o kinds presentes.

## Ronda REL 1 — `fix-and-retry`

Base exacta `origin/main=9e8898400f3e07ce5ab2a61396a38ce6dd9fd73d`;
diff REL atacado `sha256:bf821b5dade19aeeb836522c1d1bd599ef1080919f9420aaf7d697c724d1ea3a`.

| Hallazgo | Riesgo | Corrección |
|---|---|---|
| HIGH: MCP aceptaba cuatro formas conocidas que el schema success rechazaba | Publicar un resultado core inválido en vez de fallar cerrado | Validación de conflicto, `content_differs_beyond_text`, `verified_at` y relación `complete`/cursor/truncados; cuatro regresiones MCP |
| MED: upgrade beta.12 sólo ejercía un store vacío | Compatibilidad G-SUBJECT no quedaba como gate reproducible | El wheel beta.12 escribe un `subject_ref`; beta.13 conserva revisión, subject, id y texto, y el resultado valida contra el schema del wheel |
| MED: ADR-0033 aún decía “sin publicar” | Estado arquitectónico contradictorio | ADR-0033 enlaza beta.12 publicada y su evidencia adversarial |
| MED: schema no ligaba conteos legacy a `inputs.streams` | Consumidores aislados podían aceptar conteos omitidos o de streams no pedidos | Condiciones cerradas por cada stream y tres regresiones negativas |

La decisión fue `fix-and-retry`; no se añadió marker ni se creó tag o release.

## Ronda REL 2 — `fix-and-retry`

Sobre el diff inicial
`sha256:7375d430877cf8c096d7e9dba9cfbc587bb09515a5dd45c0b71f2a0338bc2eaa`,
los cuatro hallazgos de ronda 1 quedaron corregidos. Una mutación sistemática
de 4095 formas inválidas encontró tres fugas equivalentes (una por proyección):
Python trataba `freshness.stale_after_days=true` como igual al entero `1` de
inputs aunque el schema lo rechazaba. Se añadió validación entera que excluye
booleanos y una quinta regresión schema+MCP. Decisión: `fix-and-retry`; el árbol
corregido se reserva para ronda 3.

## Ronda REL 3 — `proceed`

Base exacta `origin/main=9e8898400f3e07ce5ab2a61396a38ce6dd9fd73d`;
diff final previo al marker auditado
`sha256:6fc1e5481ad5d5e3a03efed471f6583b2ba88f31060feaaa2c9d8fc90cca554f`.
No hubo hallazgos BLOCKER/HIGH/MED/LOW. La mutación sistemática rechazó las
cinco regresiones conocidas y atacó 5,422 formas success inválidas más 659
formas error inválidas, con cero fugas MCP. Las siete combinaciones no vacías
de streams conservaron correspondencia exacta con conteos legacy. Suite 511,
CI local simulado, focal 59, wheel limpio, schemas byte-idénticos y upgrade
beta.12 con subject real terminaron `OK`. Decisión: `proceed`.
