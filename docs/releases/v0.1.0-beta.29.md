# v0.1.0-beta.29 — Corrección de autoridad en checkpoint

Etiqueta publicada: `v0.1.0-beta.29` · Versión: `0.1.0b29` · Base de código:
`0947f07279ad4c8264ee6b6686bcbe6d46f69a1a` (merge del PR #137).

## Cambio

Un JSON de autoridad con `authority_class=channel_confirmed` e issuer
`channel` podía producir y confirmar un checkpoint sin resolver la autoridad
contra un adaptador de host. Esta beta rechaza esa declaración con
`channel_confirmed_requires_adapter` en plan y commit, incluida la API
directa y un plan preparado con la política anterior. El rechazo ocurre
antes de crear una transacción de checkpoint.

La política cambia su fingerprint. Replanifica cualquier checkpoint pendiente
después de instalar esta versión. El flujo permitido `model_derived` sigue
funcionando con `--emit-authority-template`.

No cambia el formato del store, `TEMPLATE_VERSION` (`0.1.0-beta.26`),
`working-state-v2`, la recuperación ni el mecanismo de resolución de
autoridad del host. `channel_confirmed` permanece indisponible para checkpoint
hasta que exista un adaptador verificable.

## Verificación y límites
