# Ronda adversarial — `v0.1.0-beta.18`

> **ESTADO: CERRADA — `proceed` con condiciones (2026-08-28).** Ronda
> adversarial de release (REL) ejecutada por panel independiente con
> contexto fresco (subagente sin contexto previo, decorrelación §1).
> La etiqueta `v0.1.0-beta.18` **ya existía** al momento de esta ronda
> (creada en `04b8b3a`, 2026-08-28T12:02Z) y la GitHub pre-release fue
> publicada (2026-08-28T16:45:28Z) **antes** de que este documento
> contuviera una decisión: secuencia invertida respecto de §1/§9
> (`docs/practicas-ingenieria.md`) y del propio marcador
> `check_release_tag.py`. La violación se registra aquí y se mitiga con
> la evidencia de esta auditoría; no invalida por sí sola la candidata
> porque la evidencia técnica verificada resulta sólida (ver Hallazgos
> H-1/H-9 y Límites). **La ronda no encontró defecto funcional
> bloqueante en POSIX.**

## Límites declarados

- **Windows diferido (decisión del operador, no re-abierta por esta
  ronda)**: la CI de Windows permanece en rojo (run 33200394865:
  15 fallos, p. ej. `test_no_allowlist_means_no_extra_vars`,
  `test_reader_gate_is_held_during_projection`,
  `test_write_error_log_appends_private_record`,
  `test_startup_diagnostic` import). Queda registrada como **limitación
  conocida de la release v0.1.0-beta.18**: la candidata se declara
  procedible para macOS/Linux; soporte Windows NO está afirmado por esta
  publicación.
- El wheel difiere del árbol del tag en `storage_primitives.py`
  (H-4); la desviación está caracterizada y es inerte en POSIX.
- GitHub Actions corre con presupuesto limitado; CI local continúa como
  gate documentado complementario.
- El marcador `an-kla:release-gate` no existe en el árbol publicado
  (H-2); añadirlo ahora mutaría el árbol post-release y no se hace.

## Condiciones del veredicto

- **C-1 (proceso, vinculante para futuras releases)**: ninguna tag ni
  release pública sin decisión REL + marcador
  `an-kla:release-gate {"decision":"proceed",...}` ya presente en el
  árbol; `check_release_tag.py` debe pasar ANTES del push del tag.
- **C-2 (documental, correctiva)**: en el próximo ciclo de release
  resolver H-5 (CHANGELOG doble estado, índice `docs/README.md`,
  frase de wheels del README) y H-6 (`check_clean_wheel` versionado
  con el bump). No requieren re-publicación de beta.18.
- **C-3 (artefacto)**: mantener registrada aquí la desviación
  tag→wheel (H-4); cualquier re-asset futuro debe construirse desde
  una revisión etiquetada sin drift.
