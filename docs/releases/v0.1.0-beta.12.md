# `v0.1.0-beta.12`

Beta.12 ejecuta el gate G-SUBJECT (issue #59 / ADR-0033): añade la identidad
contextual estable `subject_ref` v1, separada del `record.id` físico y de los
`lineage.refs`, con binding bajo `write_lock` y un comando de resolución
`subject namespace`. La release se distribuye desde GitHub mediante etiqueta
exacta; no desde `main`.

El contexto gestionado y la plantilla administrada siguen en `0.1.0-beta.11`:
beta.12 es un release de código y contrato, no de plantilla. El bloque
administrado en `AGENTS.md` y `AN-KLA.md` no cambia respecto a beta.11.

## Cambios principales

- `subject_ref` opcional y **non-authoritative**: string con forma
  `an-kla:subject:v1:<kind>:<namespace>:<id>`, enum cerrado de 11 kinds,
  ASCII lowercase reject-only (sin NFC/casefold). Cardinalidad 0-1 por record.
  No entra en `_SELF_ASSERTED_AUTHORITY_KEYS`; `evaluate_write` no lo lee para
  decidir techo de autoridad.
- Binding de namespace bajo `write_lock`: `commit_write_plan` valida, después
  de `assert_unchanged` y `verify_write_plan` y antes de construir `pending`,
  que el `namespace` declarado en cada `subject_ref` coincida con el derivado
  de `digest_bytes(binding["project_bytes"])`. Discrepancia →
  `WritePolicyError("subject_ref_namespace_mismatch")` con cero efectos (cero
  objetos, cero journal, cero revisión). La identidad migrada entre la
  consulta `subject namespace` y el commit se detecta antes, vía
  `IdentityError("store_identity_changed")`.
- Comando de resolución `subject namespace`: devuelve el `namespace` a usar en
  proposals cuando `identity_status == "complete"` (exit 0) o
  `namespace_unavailable` / null / exit 3 en caso contrario. Es **input** para
  construir proposals; el commit revalida bajo lock. No crea `.an-kla/`, no
  adquiere `write_lock`, no muta `CURRENT`.
- Schema `subject-namespace-result-v1`: shape cerrada con claves
  `{schema, result, namespace}`, condicional `allOf`/`if-then`, no expone
  `project_identity_sha256`. Copias byte-idénticas en `docs/schemas/` y
  `an_kla/schemas/`. La rama `namespace_available` ahora declara
  `maxLength: 34` junto al pattern `^p-[0-9a-f]{32}$` (Fase C L-1, redundante
  defensivo).
- `capabilities()` expone `record_validators` como mapping
  `{"subject_ref": "an-kla-subject-ref/v1", "verified_at": "an-kla-verified-at/v1"}`
  (aditivo nuevo; no enumera kinds, namespaces ni `subject_view`).
- Catálogo de drift del resolver ampliado: una carrera tras `status complete`
  que corrompa el UUID entre las dos lecturas read-only
  (`IdentityError("identity_uuid_invalid")`) ahora se mapea a
  `namespace_unavailable` / exit 3 (fail-closed), no a exit 1 (Fase C L-3).
- Compatibilidad legacy: los records previos a este gate siguen legibles sin
  cambio; `snapshot`, `verify`, `retrieve`, `refute`, `compaction` y
  `export/restore` operan sin alteración. `subject_ref` viaja verbatim al
  segmento.
- `policy_fingerprint()` cambia; todo plan pendiente debe replantearse vía
  `plan-write`. Sin migración de datos persistente.

## Límites

- Sin G-VIEW (#60): la vista contextual por `subject_ref` queda pendiente. La
  proyección a schemas v2 (retrieve/MCP/assembly) no ocurre en este release.
- Sin relaciones/endpoints/aliases: `relation` no es un kind v1; los kinds son
  atómicos. Requiere ADR posterior.
- Sin namespace cross-project: dos proyectos que mencionen el mismo externo
  producen dos subjects distintos; correlación cross-project es offline.
- Sin migración ni remapeo de namespaces tras reemplazo de anchor: si el
  anchor se reemplaza, los registros históricos retienen su namespace anterior
  y las nuevas escrituras con ese namespace fallan binding. Requiere ADR
  posterior.
- El catálogo completo de estados identity no se centraliza ahora (Fase C L-2,
  riesgo residual no bloqueante): el resolver sólo clasifica `complete` vs no-
  `complete` y expone dos valores de `result`.
- Stderr vacío sólo para los nueve estados identity clasificados y los
  `IdentityError` esperados del catálogo controlado; `OSError`/inesperados
  capturados por el handler general terminan con exit 1 y un mensaje de una
  línea que puede incluir la ruta que falló; excepciones fuera del conjunto
  capturado pueden conservar traceback. No se promete saneamiento absoluto
  (Fase C L-4).
- Python 3.9 o posterior; sin dependencias Python en runtime.

## Instalar o migrar

La instalación usa la etiqueta exacta beta.12; el contexto gestionado sigue en
beta.11, así que `context status` reporta `template_version: "0.1.0-beta.11"` y no
se requiere `context plan --operation update`. Sigue la
[guía beta.11](../beta11-user-guide.md) para una instalación nueva o migración
desde beta.8; los comandos de instalación referencian ahora `v0.1.0-beta.12`.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install \
  "an-kla-memory @ git+https://github.com/kristhianmanue1/an-kla-memory.git@v0.1.0-beta.12"
.venv/bin/python -m an_kla --version
.venv/bin/python -m an_kla --project-root . init
.venv/bin/python -m an_kla --project-root . context plan --operation install
.venv/bin/python -m an_kla --project-root . context install
.venv/bin/python -m an_kla --project-root . context status
.venv/bin/python -m an_kla --project-root . verify
.venv/bin/python -m an_kla --project-root . subject namespace
```

`subject namespace` devuelve el namespace a usar en proposals cuando la
identidad está completa; úsalo para construir `subject_ref` válidos antes de
`plan-write`.
