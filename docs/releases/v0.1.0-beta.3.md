# AN-KLA Memory v0.1.0-beta.3

Fecha: 2026-08-03

## Propósito

Esta beta añade un flujo gobernado para que agentes actualicen la integración
de AN-KLA en sus proyectos mediante un plan exacto, inspeccionable y resistente
a deriva. La instalación del paquete permanece separada y bajo autoridad del
gestor externo.

## Cambios principales

- Añade `upgrade inspect`, que produce `an-kla/upgrade-plan-v1` como JSON
  canónico sin modificar el proyecto.
- Añade `upgrade apply`, que recibe plan y fingerprint por separado, revalida
  el estado bajo lock y aplica únicamente el plan exacto.
- Añade `upgrade verify`, que comprueba versión, bloque administrado, contrato y
  manifiesto; verifica la memoria cuando existe sin inicializarla cuando falta.
- Reutiliza CAS, lock local, respaldos content-addressed y reemplazo atómico de
  `context-package/v1`.
- Rechaza referencias móviles como `latest`, tags no soportados y versiones que
  no coinciden con el ejecutable instalado.
- Expone el perfil `project-context-upgrade/v1` mediante `capabilities`.
- Empaqueta el nuevo schema normativo `upgrade-plan-v1`.
- Actualiza la plantilla de contexto a `0.1.0-beta.3` y reconoce la huella de
  `beta.1` como fuente migrable segura incluso sin manifiesto local.
- Añade una guía operativa y ADR específicos para agentes.

## Frontera de autoridad

AN-KLA no ejecuta `pip`, no descarga artefactos y no se reemplaza a sí mismo.
El operador o agente autorizado debe instalar primero una etiqueta exacta. La
memoria recuperada nunca elige la versión objetivo ni autoriza la instalación,
el commit o la publicación.

## Compatibilidad

- El formato físico de memoria definido por ADR-0001 permanece intacto.
- Recuperación, ranking y envolventes presupuestadas v1 no cambian.
- Una integración canónica `beta.1` puede migrarse a la plantilla `beta.3`.
- Ediciones locales del bloque o contrato continúan fallando en cerrado.
- Python 3.9 y 3.12 siguen soportados sin dependencias de ejecución nuevas.

## Verificación de publicación

- suite completa de 136 pruebas;
- comprobación de versión contra `v0.1.0-beta.3`;
- wheel instalado fuera del checkout;
- recorrido aislado `inspect -> apply -> verify`;
- igualdad exacta entre el schema documental y el recurso empaquetado;
- matriz CI en Linux, macOS y Windows con Python 3.9 y 3.12.

## Límites

- La instalación y rollback del paquete pertenecen al gestor externo.
- No existe restauración automática de instrucciones desde respaldos.
- El lock sigue siendo local y no coordina varias máquinas.
- MCP permanece de sólo lectura.
